How to approach a System Design question
1. Outline the Functional requirements (take only 3)
2. Outline non-functional requirements (this helps us in dives)
3. Draft the API design and make modifications as you go
4. Give very high-level design
5. Go through non-functional requirements and make the necessary modifications ^zPDFuRxh

Dropbox: The tool that lets you sync files across remote and local folder ^K7URd9kd

Functional Requirements
1. Users should be able to upload files
2. Users should be able to download files
3. Users should be able to sync files across remote and local ^3Lwqyf51

Non-functional Requirements
1. Users can be able to upload large files (~50GB)
    - resumable uploads
2. Availability >>> consistency
3. Low latency (as low as possible)
4. High data integrity ^WctisQ28

Out of scope:
1. User be able to read files without download
2. Able to give read access to others ^sp7dMG4W

For syncing the files
1. Local -> Remote
   If we make any changes to our local files,
   we can use something like FileSystemWatcher on Windows
   or FSEvents on Mac to listen for changes and we can upload 
   the changes using the same API.

   Here if we've added a change in a large file, we first chunk and compare the 
   fingerprints and only upload the ones which are different with the chunks we 
   stored in the database.


2. Remote -> Local
    We can use Polling where we periodically check for changes
    in the FileMetadata and sync the changes.
    
    We can use one more approach which is WebSockets or SSE which
    will push updates to us when there is a changes. We won't be doing
    this as this will introduce lot of overhead and operational complexity
    for this particular type of workload here. Since websockets keeps the
    connection on always, it will cause lot of problem on device and on the servers
    as well. ^FMHKMnNy

If there are multiple versions of the same file
if two persons made two different changes, the
last write wins policy should be used ^PgdaxaTt

We can also do versioning, where we keep track of version of the file
and with each update the version gets updated by 1 and the conflicts
will be resolved by looking at the version value. ^e3jJDS9M

Here, we have one more problem and that is we are getting the changes
by /getChanges?timestamp={} but the time could be different depending
on the laptop, timezones, etc. So a good approach here should be that
we keep track of an Event bus (kafka or RabbitMQ) which  keeps track of
all the changes for each file and each laptop keep track of the cursor position
it is at and it will send the /getChanges?cursor={cursor} and get all the changes
from the event bus and updates the cursor. ^VQ0XUmwx
